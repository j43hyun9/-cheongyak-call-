## 그림 1 — `/chat` 요청이 백엔드 내부를 지나가는 경로

캐시 미스 시 정상 흐름(①~⑤)과, 캐시 히트 시 단축 경로(점선)를 함께 표시. 단축 경로는 `sources`를 저장하지 않아 RAG 근거가 빠지는 알려진 한계(2026-08-21 발견)와 직결됨 — §7 "테스트 결과와 한계"에서 재사용.

```mermaid
flowchart TB
    Client["React 프론트엔드<br/>ColbyAvatarPage"]
    Hub["backend/main.py<br/>/chat 핸들러"]

    Client -- "POST /chat {session_id, message}" --> Hub

    Hub -- "① 조회" --> Cache["cache.py<br/>응답 캐시"]
    Hub -- "② 검색 (미스 시)" --> RAG["rag/colbi_rag.py<br/>retrieve() → context, sources"]
    Hub -- "③ 조립" --> Persona["persona/colbi.py<br/>build_messages()"]
    Hub -- "④ 호출" --> LLM["llm.py<br/>call_llm()"]
    Hub -- "⑤ 저장" --> DB["db.py<br/>history · call_log"]

    Cache -.->|"in-memory dict, TTL 1시간"| CacheStore[("in-memory")]
    RAG -->|"앱 시작 시 1회 로드"| FAISS[("FAISS 인덱스<br/>schedule/concept 분리")]
    LLM -->|"engine=local"| Ollama[("Ollama 서버<br/>colbi-qwen")]
    LLM -->|"engine=openai (폴백)"| OpenAI[("OpenAI API")]
    DB --> SQLite[("colby.db (SQLite)")]

    Hub -. "캐시 히트 시 단축 경로<br/>②~⑤ 생략, sources=[] 반환 ⚠" .-> Client

    style Hub fill:#e1eaf4,stroke:#2b5fa5
    linkStyle 6 stroke:#b5651d,stroke-dasharray:5 3
```

**해석**: 정상 흐름(실선)은 캐시 미스일 때만 RAG→persona→LLM→DB를 전부 거친다. `cache.set()`이 답변 텍스트만 저장하고 `sources`는 저장하지 않기 때문에, 같은 질문이 캐시에 걸리면(점선) RAG 근거 표시가 빈 배열로 나간다 — RAG 재도입의 핵심 가치(근거 기반 답변)와 충돌하는 구조적 버그. PM·장두호에게 전달 완료, 아직 미수정.

## 그림 2 — 발화 한 턴의 API 호출 순서와 아바타 상태

```mermaid
sequenceDiagram
    participant U as 사용자(마이크)
    participant F as 프론트엔드(ColbyAvatarPage)
    participant S as POST /stt
    participant C as POST /chat
    participant T as POST /tts

    Note over F: state = listening
    U->>F: 발화 녹음
    F->>S: audio
    S-->>F: {text}
    Note over F: state = thinking
    F->>C: {message}
    C-->>F: {answer_text, sources}
    Note over F: state = speaking
    F->>T: {text}
    T-->>F: audio/mpeg
    F->>F: 재생 + 립싱크(useSpeakingMouth)
```

**해석**: 아바타 상태(idle→listening→thinking→speaking)는 API 경계와 정확히 겹치지 않는다 — listening은 녹음+STT 응답 대기를 모두 덮고, speaking은 TTS 호출+재생을 모두 덮는다. `/chat`은 내부적으로 STT·TTS를 호출하지 않으며, 프론트가 4단계를 순차 호출해 조합하는 구조다(2026-08-14 팀 확정 설계 — 스트리밍 미사용, 동기 요청/응답).

**⚠️ 이 그림은 목표 파이프라인이다.** 2026-08-21 기준 `/stt`·`/chat`·`/tts` 개별 API는 각각 동작이 검증됐지만, 프론트엔드 마이크 버튼이 이 4단계를 실제로 순차 호출하도록 연동하는 작업은 진행 중이다(백승옥 담당, PR#19는 아바타 UI·상태머신까지만 완료).
