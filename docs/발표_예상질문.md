# 콜비 발표 — 예상 질문 & 답변 스크립트

발표/심사 대비 Q&A. 특히 방어 취약점(LLM-judge 신뢰성·과적합)에 대한 답변 준비.

## Q1. RAG를 왜 뺐나?
- 2차의 초점은 **"어투 파인튜닝"**. RAG(실시간 크롤링 주입)는 **프로젝트3에서 다룰 기술**이라 범위 분리.
- 크롤러·`/ipo/schedule`·캘린더는 **UI 기능으로 유지**하고, 챗봇이 일정을 지어내지 않도록 **"캘린더에서 확인" 유도**로 설계 → 할루시네이션 방지와도 일치.

## Q2. held-out PASS 30/30 — 과적합/평가 부풀림 아닌가?
- 평가셋 30문항은 **held-out**(학습 제외). 전처리에서 학습셋과 **정규화 중복 0** 확인, 패러프레이즈로 겹치던 7문항도 교체.
- 채점은 **5축 루브릭 + 치명축(가드레일·사실성) 위반 시 1점** 규칙 → 단순 만점 방지장치.
- **자기채점 우려 방어**: 판정 모델은 우리 파인튜닝 모델이 아니라 **독립 심판(GPT-4o)**. 루브릭을 공개했고, 정성 전/후 비교로 교차 검증. (한계로 "LLM-judge라 인간평가로 보강 여지" 솔직히 인정)

## Q3. 과적합은? val 지표는?
- 데이터를 **train 180 / val 20**으로 분리해 학습. 3 epoch(어투 style-transfer엔 과하지 않은 범위).
- 과적합 징후 확인: held-out 30문항에서 **일반화 성능(PASS 30/30)** 이 유지됨 → 학습셋 암기가 아니라 어투가 일반화됨을 시사.
- (보강 여지: val loss 곡선·조기종료 미세 튜닝은 향후 과제.)

## Q4. 6초 지연 — 실서비스 가능한가?
- 현재는 **로컬 CPU 서빙** 기준. **GPU 서빙 시 대폭 단축**, 또는 **Qwen2.5-3B 경량화**로 개선 가능.
- 실운영은 **클라우드 GPU + 컨테이너(Docker)** 로 확장 (부트캠프 범위 밖, 향후 계획).

## Q5. 200건으로 충분한가? 데이터는 어떻게?
- **어투 style-transfer는 소량으로도 효과** — persona-driven **합성 생성**(few-shot·페르소나 카드 시드 → LLM 증강) 후 **전수 사람 검수**(가드레일·할루시 커버).
- 품질검증: 카테고리 분포 균형 + 어투 일관성 검수 + held-out 분리로 평가 신뢰성 확보.

## Q6. 파인튜닝이 프롬프트 대비 실익이 있나?
- **결정적 증거(전/후)**: base Qwen은 **존댓말·중국어 혼입·"어른처럼" 요청에 순응(페르소나 이탈)** → 파인튜닝 콜비는 반말 탐정 어투·가드레일·정체성 방어 일관.
- 게다가 **few-shot 없이도(slim) 어투 유지** → 어투가 가중치에 내재화됨(프롬프트 토큰 831→422 절감).

## Q7. 왜 Qwen2.5-7B? 왜 로컬?
- 한국어 성능 우수 + **Apache 2.0**(상업 부담 적음) + 무료 Colab QLoRA 가능.
- 로컬(Ollama): **토큰 비용 0 · 자율성** (강사 권고 "사전학습모델 가져다가 튜닝" 취지 부합).

## Q8. 팀 협업은 어떻게?
- GitFlow(feature→PR→merge), CLAUDE.md 공통 맥락, 일별보고. 방향 전환도 팀 합의 후 인계점 갱신.
