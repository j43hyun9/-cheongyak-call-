## 그림 A — 엔진별 지연시간 실측

같은 4개 도메인 문장(gTTS 생성 음성)을 세 엔진에 동일하게 통과시킨 결과.

| 엔진 | 지연 범위(요청당) | 최초 모델 로드(1회성) |
| --- | --- | --- |
| Whisper API (클라우드, 현재) | 1,000–2,250ms | — (클라우드) |
| faster-whisper (로컬, 현재) | 468–1,562ms | 687ms |
| SenseVoice (로컬, 검토 후보) | 187–342ms | 1,906ms |

로컬 엔진이 빠르지만(SenseVoice는 Whisper API의 최대 1/8), 정확도는 아래 그림 B·C에서 따로 봐야 한다 — 속도와 정확도가 같은 방향으로 움직이지 않는다.

## 그림 B — 도메인 문장 인식 정확도 패턴

| 문장 | 유형 | Whisper API | faster-whisper | SenseVoice |
| --- | --- | --- | --- | --- |
| "공모주 청약 일정 알려줘" | basic | ✅ | ✅ | ✅ |
| "기도산업 청약 일정 알려줘 공모가는 얼마야" | 고유명사·전문용어 | ✅ 완전 일치 | ❌ "국무관"으로 오인식 | ❌ "공무관"으로 오인식 |
| "균등배분이랑 비례배분 차이 설명해줘" | 전문용어 | ✅ | ❌ 문장 붕괴 | ✅ (띄어쓰기만 차이) |
| "따상이 뭐야" | 슬랭 | ❌ "빠상" | ❌ "따 3" | ❌ "빠 상" |

전문용어는 Whisper API가 3/3 성공으로 확실히 우위(faster-whisper `base`는 도메인 힌트 프롬프트를 넣어도 한계가 뚜렷). 슬랭은 3개 엔진 전부 실패 — 모델 크기가 아니라 학습 데이터 자체에 이 단어가 거의 없어서로 추정, STT 레벨보다 RAG concept 문서 보강이 더 현실적인 해법.

## 그림 C — 한국어 STT 공개 CER 벤치마크 순위 (10개 서비스)

출처: `rtzr/Awesome-Korean-Speech-Recognition`(리턴제로 공개, AI-Hub 6개 데이터셋·서비스당 3,000문장, CER 기준). 1위가 자사 발표라 편향 가능성은 있으나, 방법론이 공개돼 있고 순위 경향(한국어 특화 엔진 > 글로벌 빅테크 > Deepgram)은 알려진 경향과 일치.

| 순위 | 서비스 | CER |
| :--: | --- | :--: |
| 1 | 리턴제로(RTZR) 자체엔진 | 5.91% |
| 2 | 리턴제로 Whisper(자사튜닝) | 6.59% |
| 3 | 네이버 클로바 스피치 | 7.52% |
| 4 | ETRI 공공 AI | 10.19% |
| 5 | Azure Batch STT | 10.88% |
| 6 | AWS Transcribe | 11.11% |
| **7** | **OpenAI Whisper (우리 엔진)** | **11.34%** |
| 8 | Google Speech v2 | 11.59% |
| 9 | Gemini 2.0 Flash | 14.48% |
| 10 | Deepgram (nova-2) | 21.18% |

우리가 쓰는 OpenAI Whisper는 10개 중 7위(중위권) — 한국어 특화 엔진 대비 오차율이 거의 2배지만, 나쁘지 않은 선택이었음을 뒷받침.

## 결론 (선정 근거 요약)

1·2차엔 조사 시점 한국어 인식률과 강사 추천으로 Whisper API를 채택했고, 3차 재사용은 결제해둔 토큰이 남아 재조사 없이 이어감. GPU 없는 팀 환경을 위해 3차에 `faster-whisper` 로컬 엔진을 추가(엔진 추상화, PR#14). 실측 결과 전문용어는 Whisper API가 우위, 지연은 로컬이 우위라 상황별 선택지로 그대로 공존시킴. `SenseVoice`는 속도·정확도 모두 `faster-whisper`보다 나아서 다음 교체 후보로 남겨뒀고(코드 미반영), `Deepgram`은 스트리밍 구조 미스매치 + CER 최하위로 비채택. "따상" 같은 슬랭은 STT 레벨이 아니라 RAG concept 문서 보강이 정공법.
